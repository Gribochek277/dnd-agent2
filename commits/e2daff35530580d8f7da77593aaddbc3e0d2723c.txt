feat: surface deterministic system events (dice rolls & tool calls) before DM narration
The player now sees the mechanical ground truth — dice, HP changes, DCs, loot,
gold, XP — as dim system lines rendered before the DM narration streams:

- Add ToolCallEvent and extract FunctionCallContent/FunctionResultContent pairs
  from update.Contents in ChatClientAgentStreamSource.CollectNarrationAsync
  (matched by CallId), forwarding each completed tool call via onToolEvent.
- Thread onToolEvent through ILlmClient.SendPromptStreamingAsync →
  DmAgent.SendAsync → InputLoop; the enemy turn (EnemyAIService, incl. its own
  AttackRoll/ApplyDamage resolution events) and GenerateStartingSceneAsync
  propagate events too.
- Add IToolEventFormatter/ToolEventFormatter: ApplyDamage→⚔️ −N HP (cur/max),
  TriggerSave→🎲 спасбросок … d20=… → успех/провал, AssignDC→🎯 СЛ N,
  StartCombat/EndCombat→⚔️ (EndCombat + «✨ XP» when XP is granted),
  GrantLoot/SpendGold→💰, Heal→💚; rejected calls render dim as «⚠ … Rejected: …»
  so they are never shown as an accomplished fact.
- ConsoleRenderer.RenderToolEvent styles system lines gray (dim for rejected);
  events fire while the pass is still collected, before any narration token, so
  the DmStreamRenderer block cursor is never left in front of them.
- EndCombatTool now computes XpToGrant from defeated enemies and reports
  «XP granted: N» in its result, so the XP event line is always truthful and the
  DM-tool combat-end path grants XP consistently with the enemy-turn path.
