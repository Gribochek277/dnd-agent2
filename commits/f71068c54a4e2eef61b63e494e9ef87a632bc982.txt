message:
fix(#39): expose and forward isCheck through the TriggerSave tool contract
DmAgentToolProvider registered TriggerSave as a 3-argument func
(target, ability, isDeathSave), so the isCheck parameter added to
TriggerSaveTool/ExecuteWithPayload never reached the tool from the LLM —
an ability check was silently rendered as «спасбросок» even though the
tool description told the model to set isCheck. This is the actual path
where the #39 label bug persisted.

- Register the tool with a 4-argument Func so isCheck is exposed to and
  forwarded by the AIFunction.
- Add a regression test that invokes the AIFunction with isCheck=true
  through Microsoft.Extensions.AI and asserts the message reads
  «Ability check» (would fail if the wiring is dropped again).
