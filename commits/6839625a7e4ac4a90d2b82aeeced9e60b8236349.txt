feat: add config-driven LLM compat layer (port of pi openai-completions)
ModelCompat/ModelCompatDetector resolve the request shape per provider:
llama.cpp (default profile) -> max_tokens + qwen-chat-template thinking
(chat_template_kwargs.enable_thinking=false, preserve_thinking=true);
opencode-go/deepseek -> deepseek thinking (thinking:{type} +
reasoning_effort) plus reasoning-replay requirements. Explicit Compat
config overrides the detected defaults.

LlmConfig gains Provider/ApiKey/Reasoning/ThinkingLevel/Compat, bound
from the LLM section (appsettings + LLM__* env vars). DmAgentFactory
resolves compat through the detector and hands the request to
OpenAiRequestCustomizer, which injects body patches via
RawRepresentationFactory/ChatCompletionOptions.Patch: max_tokens vs
max_completion_tokens, store opt-out, stream_options.include_usage,
thinking params by ThinkingFormat and extra sampling params.

RequiresReasoningContentOnAssistantMessages is exposed as an extension
point for the DeepSeek reasoning-replay middleware (#7); it is not yet
applied by the agent loop. Default llama.cpp/Qwen behavior unchanged
(verified live against the llama.cpp endpoint).
