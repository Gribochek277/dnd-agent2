feat(combat): system combat entry on player attack (issue #27)
A player attack in Exploration now ALWAYS reaches Combat, even when the
model stays silent and never calls StartCombat. After the existing
bounded passes (issue #12, StartCombat requirement) the turn
orchestrator guarantees the transition:

- system StartCombat with the party + participants from the last
  DeclareEncounter call (now recorded on the state context);
- if no encounter was declared, one re-request of the turn demanding
  DeclareEncounter (bounded single corrective iteration + fallback
  note), then system start;
- last resort: the attack target from the player's own message.

Peaceful actions (no attack intent) never start combat. The start
flow is shared between the StartCombat tool and the system fallback
via the new ICombatStartService.
