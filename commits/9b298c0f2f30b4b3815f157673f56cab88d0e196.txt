fix(dm): fair combat — state-aware tool guidance, no self-attack, turn-scoped enforcement (#139)
Live `enemy-declared-into-combat` scored `fair: 2` (0/3): a rejected AttackRoll
answered with the false instruction «call StartCombat first» while combat was
already active, so the model oscillated AttackRoll/DeclareEncounter/StartCombat
until the turn ended in a system note.

- ToolFailureReporter: state-aware guidance for AttackRoll/ApplyDamage/Heal —
  during an active fight never send the model back to StartCombat; forbid the
  repeat and point at the real state. Combat-not-active still points at
  DeclareEncounter + StartCombat.
- AttackRollTool: reject a self-attack (target == current combatant) — the tool
  always rolls for the acting combatant, so the DM's attempt to resolve an
  enemy's bite by targeting the player would silently become a self-hit.
- PromptBuilder: turn ownership — one turn resolves only the acting combatant's
  action; the system runs the other combatants' turns.
- ChatClientAgentStreamSource: make StartCombat/DeclareEncounter requirements
  turn-scoped — once satisfied in an earlier pass, a corrective pass is no
  longer forced to repeat it (removes the false «combat did not start» note).
