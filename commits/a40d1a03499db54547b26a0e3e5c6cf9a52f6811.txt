fix(dm): enforce StartCombat when the DM narrates combat start (issue #12)
The DM could narrate enemies entering combat ("Битва начинается!", "Химера-страж
делает выпад") without calling StartCombat, leaving the game in Exploration with
no initiative or combat state — reproduced twice on playtest.

Mechanism (system-prompt rule + loop guard):
- PromptBuilder system prompt: combat is a system state; enemy attack / battle
  start MUST be preceded by a StartCombat call while in Exploration.
- New ICombatStartMarkerDetector (RU/EN): battle-start declarations, present-tense
  transitions into the fight, and hostile-action verbs. Imminent-future setup,
  retrospective and peaceful scenes deliberately do not match (no false positives).
- TurnPassAdjudicator: new RetryCombatStart action when requireCombatStart is set,
  markers are present, and no accepted StartCombat call ran this turn.
- ChatClientAgentStreamSource: exactly one corrective iteration demanding
  StartCombat; a repeated violation ends the turn with a system note (state
  unchanged) instead of the false battle narration.
- CLI DmAgent passes requireCombatStart only from Exploration (where StartCombat
  can run); combat-in-progress and non-player-facing turns are unaffected.

Tests: 19 new cases — detector positives/negatives (incl. the two repro phrases
and peaceful scenes), adjudicator combat-start scenarios (accepted/rejected
StartCombat, flag off, peaceful), stream-source corrective iteration (one-shot,
fallback note), LlmClient flag forwarding, and DmAgent state→flag wiring.
dotnet build: 0 errors (known NU1903/CS8632 only). dotnet test: 570/570 green.
